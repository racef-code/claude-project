# Virtual Try-On MVP

A minimal Virtual Try-On (VTO) web application that lets users upload a photo and see themselves wearing garments from your catalog using AI image generation.

## Features

- Simple catalog grid display
- User photo upload (drag-drop or click)
- AI-powered virtual try-on using Google Gemini 2.0 Flash
- Side-by-side comparison (original vs try-on)
- Responsive design (works on mobile)
- No frameworks - pure HTML/CSS/JS

## Tech Stack

- **Backend**: Python Flask
- **Frontend**: Vanilla HTML/CSS/JavaScript
- **AI Model**: Google Gemini 2.0 Flash via `google-generativeai` SDK
- **Image Processing**: Pillow (PIL)

## Setup Instructions

### 1. Install Dependencies

```bash
cd vto-mvp
pip install -r requirements.txt
```

### 2. Configure API Key

Create a `.env` file with your Google API key:

```bash
cp .env.example .env
# Edit .env and add your GOOGLE_API_KEY
```

To get a Google API key:
1. Go to [Google AI Studio](https://aistudio.google.com/app/apikey)
2. Create a new API key
3. Copy it to your `.env` file

### 3. Add Catalog Images

Add your garment images to `static/catalog/`:

- `item_001.jpg` - Linen Blazer
- `item_002.jpg` - Cotton Tee
- `item_003.jpg` - Denim Jacket

**Image Requirements**:
- Format: JPG or PNG
- Recommended size: 600x800px or similar portrait orientation
- Clear view of the garment
- Plain or simple background works best

**Option 1: Create Placeholder Images**

Run the placeholder generator (requires Pillow):

```bash
python create_placeholders.py
```

**Option 2: Use Your Own Images**

Simply copy your garment photos to `static/catalog/` with the filenames above.

### 4. Customize Catalog

Edit `catalog.json` to update item names, prices, and AI prompts:

```json
{
  "items": [
    {
      "id": "item_001",
      "name": "Your Item Name",
      "image": "catalog/item_001.jpg",
      "price": "€129",
      "prompt": "Detailed description for AI..."
    }
  ]
}
```

### 5. Run the Application

```bash
python app.py
```

Visit `http://localhost:5000` in your browser.

## Usage

1. **Browse Catalog** - View available garments on the homepage
2. **Click "Try It On"** - Select a garment you want to try
3. **Upload Photo** - Upload a selfie or full-body photo
4. **Generate** - Wait 10-20 seconds for AI processing
5. **View Results** - See yourself wearing the garment!
6. **Try Another** - Keep your photo and try different items

## API Endpoints

### `GET /`
Returns the main HTML page

### `GET /catalog`
Returns catalog items as JSON

### `POST /try-on`
Generates virtual try-on image

**Request:**
```json
{
  "user_image": "data:image/jpeg;base64,...",
  "item_id": "item_001"
}
```

**Response:**
```json
{
  "success": true,
  "generated_image": "data:image/jpeg;base64,...",
  "item_name": "Oversized Linen Blazer"
}
```

## Customization

### Add More Items

1. Add image to `static/catalog/`
2. Add entry to `catalog.json` with unique ID
3. Write a detailed prompt describing the garment

Edit `static/css/style.css` to change:
- Colors and fonts
- Grid layout
- Button styles

### AI Prompts

Each item has a custom prompt that guides the AI. Include:
- Garment type and style
- Color and fabric details
- Fit and silhouette
- Key features
- Instruction to preserve person's appearance

## Troubleshooting

### "GOOGLE_API_KEY not configured"
- Make sure `.env` file exists and contains your API key
- Restart the Flask app after adding the key

### "No image generated by the model"
- The Gemini API may have rate limits - wait and retry
- Check your API key is valid
- Verify the model name is correct (`gemini-2.0-flash-exp`)

### Images not loading
- Check that files exist in `static/catalog/`
- Verify filenames match those in `catalog.json`
- Check file permissions

### Slow generation
- Gemini API can take 10-30 seconds depending on load
- This is normal for image generation
- Consider adding retry logic for timeouts

## Production Considerations

This is an MVP. For production, consider:

- **Image Storage**: Use cloud storage (S3, etc.) instead of local files
- **Queue System**: Process requests asynchronously (Celery, etc.)
- **Caching**: Cache generated images to avoid re-generation
- **Rate Limiting**: Prevent API abuse
- **User Accounts**: Track user sessions and history
- **Error Handling**: More robust error handling and logging
- **Security**: Add CSRF protection, input validation, file size limits
- **Monitoring**: Add analytics and error tracking
- **Scale**: Use a production WSGI server (Gunicorn, etc.)
